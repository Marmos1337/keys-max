# Ключи — MAX × Умный город

Версия **0.3.6**, схема SQLite **3**. Мини-приложение + MAX Bot для собственника
и арендаторов. Основа этого обновления — переданный архив `keys-max-0.3.5.zip`,
не копия текущего production-сервера.

## Новое в 0.3.6 — удаление квартиры

Внизу **Квартиры → карточка → Обзор** добавлена отдельная кнопка «Удалить квартиру».
Она доступна только собственнику. Сначала открывается подтверждение с названием,
адресом, составом удаляемых данных и кнопками «Отмена» / «Удалить квартиру».
Открытие окна и отмена ничего не меняют.

Удаление действительно убирает квартиру, её комнаты, аренды, записи и файлы из
приложения, а не просто скрывает карточку. Действующие аренды с жильцами и
неурегулированные расчёты блокируют удаление. История законченных аренд тоже
удаляется — это явно указано в подтверждении. Перед удалением сохраните нужные
документы и резервную копию. Остальные квартиры и учётные записи не затрагиваются.

Изображения, три обложки, переключение ролей и временный гайд из 0.3.5 сохранены.
Результаты текущих тестов: [docs/TEST_REPORT.md](docs/TEST_REPORT.md).

## Что реализовано

Квартиру можно сдавать целиком или сдавать одну/несколько её комнат независимо.
В каждой отдельной аренде может быть несколько приглашённых жильцов. Сумма аренды
общая за объект, не умножается на количество участников. Жильцы одной аренды видят
общие документы и записи; другая комната и другой период аренды изолированы.

Оплата частями: каждый жилец сообщает фактически переведённую им сумму, собственник
подтверждает каждый перевод отдельно. Остаток уменьшается после подтверждения,
а ожидающие переводы резервируют остаток от случайной переплаты. Автоматические
обязательные доли по людям не назначаются. Банковские операции не выполняются.

Счётчики настраивает собственник: произвольные названия, несколько приборов одного
типа, вода/газ/электричество/отопление/другой тип; 1/2/3 тарифа, начальное показание,
архивирование. Общие приборы квартиры и отдельные приборы аренды/комнаты. Передачу
можно отключить. Числовые общие показания видны другим комнатам, но не чужие фото,
договоры или обсуждения. Поставщикам/ЖКХ показания автоматически не отправляются.

Ежемесячные правила: создание отдельного правила либо флажок «Повторять ежемесячно»
в начислении; сумма, день, период, заблаговременность 1–60 дней (по умолчанию 14).
Список правил, изменение с будущего месяца, пауза, возобновление, удаление правила
без удаления выставленных счетов. Даты 29–31 в коротких месяцах обрабатываются
корректно. Изменение суммы самой аренды требует согласования всеми жильцами.

Заявки: собственник сообщает о ремонте, автор-арендатор подтверждает устранение;
состояние «Ждёт арендатора» не попадает в решённые заявки. Сохраняются покупки,
компенсации, посещения с согласованием/встречным временем, документы, экспорт,
фото квартиры, профиль и история. Посещения/условия/завершение требуют ответов
участников соответствующей аренды, а не случайного пользователя другой комнаты.

Приглашение production начинается в MAX Bot с персональной одноразовой ссылки
на 72 часа. Бот показывает контекст и просит подтвердить присоединение; затем
открывает нужную аренду. Уведомления содержат автора, объект и содержание события.
Кнопки ведут к записи, обсуждению, счётчикам или аренде, не всегда на главную.

Светлая/тёмная тема, выбор в профиле, адаптивный логотип, мобильные отступы,
упрощённый договор, недублирующая навигация. Ввод дат: ДД.ММ.ГГГГ, месяцев: ММ.ГГГГ.
Оригинальные логотипы и изображения предыдущей версии сохранены.

## Локальный запуск

Требуется Node.js не ниже 22.16 (проверено на 22.16.0).
Windows: `start-windows.cmd`. macOS/Linux: `sh start-unix.sh`.
Либо в терминале:

```sh
npm run setup
npm start
```

Открыть `http://localhost:3000` → «Попробовать демо» → выбрать роль.
Сервер сохраняет изменения в `data/keys.sqlite` и `data/uploads/`.
`npm install` не нужен: внешних runtime npm-зависимостей нет.
При локальном Docker: `docker compose up --build -d`.
Не используйте реальные документы в деморежиме; production с демонстрационной БД
запускаться не должен. Это серверное приложение, не статический index.html.

## Production

Подробно: [docs/DEPLOY.md](docs/DEPLOY.md), [docs/MAX_SETUP.md](docs/MAX_SETUP.md).
Основная команда для предоставленного окружения:

```sh
docker compose -p keys-prod -f compose.yaml -f compose.prod.yml -f compose.ca.yaml up -d --build
```

Применять только после копии и проверки конфигурации. Рабочие токены и сеансовые
секреты не вложены; `.env.production.example` содержит лишь публичные параметры
`keys.udav.team`, `reports@udav.team` и пустые значения секретов.
Публичные `/privacy` и `/terms` получили общий визуальный стиль. Тексты разделов
сохранены относительно 0.3.0; страницы по-прежнему доступны без авторизации.

## Ограничения

Нет банковского эквайринга, автоматической передачи показаний, налоговой отчётности,
электронной подписи и проверки права собственности. Нет автоматического распределения
общих коммунальных расходов по людям/комнатам. Общая аренда и аренда её комнат не
могут быть активны одновременно; следующую аренду объекта создают после завершения
предыдущей. Присоединение нового человека к существующей аренде даёт ему доступ
к общей истории именно этой аренды; для нового состава на новом периоде создайте
новую аренду, не добавляйте людей в старую историю по ошибке.

Пилот — один Node-процесс и SQLite на локальном диске. Горизонтальное масштабирование,
массовая нагрузка, native iOS/Android/MAX и Docker-сборка здесь не проверялись.
Документы ограничены ACL, но хранилище не шифруется самим приложением; права ОС,
TLS, резервные копии, сроки хранения и доступ администраторов настраивает оператор.
