# Обновление 0.3.3 → 0.3.5

Архив подготовлен на основе 0.3.3 из переписки. Если после неё код менялся на
сервере или в Codex, сначала совместите изменения. Не заменяйте неизвестные
изменения на сервере вслепую.

## Перед обновлением

Сделайте резервную копию базы, загруженных файлов и конфигурации текущей
установки. Используйте существующий процесс резервного копирования либо
`npm run backup` из старой рабочей папки с её настройками. Проверьте, что копия
действительно создана и находится вне заменяемых исходников.

Сохраните рабочий `.env`, `DATA_DIR`, Docker-том, сертификаты вашей установки,
параметры MAX и reverse proxy. Не переносите демонстрационные данные поверх
рабочих. В этом ZIP нет рабочей базы и секретов.

## Что обновить

Нужно обновить весь комплект исходников, а не только `styles.css`:

- `public` — общий интерфейс и логика временного гида;
- `server` — новый защищённый метод сохранения прогресса гида и единая версия;
- `package.json` — версия 0.3.5;
- тесты и документация.

Перезапустите приложение вашим обычным способом. При Docker — пересоберите
существующий сервис без удаления тома данных; не используйте `down -v`.
Имена томов, домен, порты и настройки Nginx Proxy Manager менять не требуется.

Схема SQLite остаётся **3**. Новое состояние гида хранится в существующем JSON
настроек пользователя. Передача показаний, суммы, участники и файлы не мигрируются.

## Приёмка

Проверьте `/api/health`: должна отображаться версия `0.3.5`. Закройте и заново
откройте Mini App, чтобы получить новые JS/CSS. Убедитесь, что прежние квартиры,
комнаты, платежи и фотографии сохранились. Пройдите сценарий в
`ПРОВЕРКА_ДЛЯ_ЗАКАЗЧИКА.md`, включая аккаунт с двумя ролями и скрытие гида.

Из чата ничего не выкладывалось на `keys.udav.team`. Не подменяйте эту проверку
локальными скриншотами: реальный клиент MAX, мобильная клавиатура, safe area и
поведение кнопки закрытия требуют приёмки на устройствах.

## Откат

Сохранённый предыдущий код можно вернуть без новой миграции БД. Поле `guide_v1`
в JSON настроек не меняет схему и не даёт дополнительных прав. При восстановлении
базы из резервной копии учитывайте новые данные пользователей, появившиеся после
её создания: не теряйте их из-за автоматического отката.
