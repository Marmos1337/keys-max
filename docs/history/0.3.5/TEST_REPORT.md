# Проверка «Ключей» 0.3.4

Дата: 25 сентября 2026. Основа — исходники архива keys-max-0.3.3.zip.
Только тестовые пользователи, квартиры и документы. Production-данные не использовались.

Итого **945 проверок геометрии** — это комбинации экрана/состояния, роли, темы и
размера окна, а не 945 разных страниц. Проверены размеры 320, 360, 390, 600, 760,
768, 980, 1024 и 1440 CSS px; дополнительно — узкие окна высотой 480 px.
В основных browser-прогонах ошибок JavaScript (`pageerror`) не зарегистрировано.
JSON-отчёты в этой папке содержат конкретные случаи; `node-test-output.txt` —
фактический вывод 137 тестов. Старые отчёты перенесены в `history/0.3.3` и не
служат доказательством проверки этой поставки.

## Что охвачено

Вход, выбор режима, главная, квартира и все пять вкладок, счётчики, заявки,
финансы, регулярные платежи, документы, покупки, посещения, история, профиль,
уведомления. Отдельные режимы собственника и арендатора плюс один настоящий
тестовый аккаунт, одновременно сдающий собственное жильё и снимающий чужое.

Подробности заявки, покупки, посещения, начисления, показаний, документа, расхода,
новых условий и завершения аренды. Формы создания/редактирования квартиры и фото,
комнаты, аренды, счётчика, регулярного правила, заявки, покупки, документа,
расхода, посещения, условий, завершения; также приглашение, вход по коду, помощь,
экспорт и безопасность. Формы действий подтверждения/возврата/отклонения проходят
с обеих доступных сторон. Формы прокручиваются до последней кнопки; проверяется,
что она действительно доступна для нажатия, а не прикрыта другим элементом.

Дополнительные случаи: пустой кабинет, архивный период, отсутствие счётчиков,
несколько жильцов и комнат, длинные непрерывные имена и названия, крупная сумма
с копейками. Сохраняются точные числа; ₽ не отрывается от суммы.

## Найденные и исправленные проблемы

1. Плавающая панель действий перекрывала данные согласования; она теперь в потоке.
2. Несогласованные ширины/высоты парных действий; исправлена единая grid-сетка.
3. Видимая подсказка формата даты поднимала один лейбл над другим; подпись больше
   не ломает ряд, формат остаётся в placeholder и доступном имени поля.
4. CSS background у полей стирал стрелки select; заменён на background-color.
5. Вкладки договора/оплаты/истории показаний давали карточки без расстояния;
   они переведены на общий контейнер списка.
6. Длинное имя растягивало профиль, автора истории и подписи; исправлены min-width
   и переносы текста. Обнаружено именно через проверку узкого экрана.
7. Суммы статистики и подробностей переносились/вылезали; используются неразрывные
   значения и подбор размера, для экстремальных сумм — отдельная широкая карточка.
8. Счётчики переносили ввод вниз из-за min-width; строки используют общую сетку.
9. В одиночном режиме в шапке оставалась пустая строка; теперь она условная.
10. Низкое desktop-окно не помещало sidebar; минимальная высота снята, есть прокрутка.

## Проверка временного гайда

- Первые три открытия оставляют подсказку, четвёртое скрывает её.
- После нового сеанса и перезапуска сервера скрытие сохраняется.
- «Профиль → Помощь» по-прежнему открывает гайд, не возвращая баннер.
- Четыре разных самостоятельных тематических перехода скрывают подсказку.
- Повторное посещение одного раздела и переход из самого гайда не увеличивают
  количество самостоятельных разделов. Перезагрузка не считается открытием гайда.
- Явное скрытие работает сразу и сохраняется.
- Разделение пользователя/режима и монотонное объединение запоздалых запросов
  проверены отдельными API/unit тестами. Новая миграция БД не требуется.

## Среда и ограничения

Node.js + SQLite обслуживали настоящие HTTP-запросы локально. Chromium рендерил
реальные HTML/CSS/JS исходники. В этой среде нативная навигация Chromium к localhost
блокируется политикой браузера (`ERR_BLOCKED_BY_ADMINISTRATOR`), поэтому для UI
использован существующий тестовый режим `--embedded`: DOM монтируется в браузере,
а запросы направляются через Python-мост к реальному серверу. Политика браузера
не менялась, авторизация приложения не отключалась в production-коде.

Следовательно, эти результаты **не являются тестированием настоящего MAX**.
Android/iOS WebView, WebKit/Safari, физическая клавиатура телефона, нативный history/
BackButton MAX, CSP в реальной загрузке, live webhook и Docker-сборка здесь не
проверены. Это остаётся отдельной приёмкой после развёртывания. Изменения
не выкладывались на keys.udav.team.

## Воспроизведение

Runtime приложения не требует новых npm-зависимостей. Для browser-тестов отдельно
нужны Python, Playwright и установленный Chromium. По умолчанию browser-тесты
используют обычный HTTP; `--embedded` нужен только для ограниченной среды.

```sh
node scripts/check.mjs
python tests/browser_visual_system.py --embedded --chromium /usr/bin/chromium
python tests/browser_full_audit.py --embedded --chromium /usr/bin/chromium
python tests/browser_smoke.py --embedded --chromium /usr/bin/chromium
python tests/browser_feedback.py --embedded --chromium /usr/bin/chromium
python tests/browser_revision_v3.py --embedded --chromium /usr/bin/chromium
python tests/browser_legal.py --embedded --chromium /usr/bin/chromium
python tests/fresh_start.py
```

Длинные screenshots `full_page` могут показывать фиксированное нижнее меню внутри
общего изображения: это позиция меню в момент съёмки. Проверки прокрутки и реального
нажатия отдельно подтверждают доступность элементов. Для быстрой оценки есть
viewport-снимки, а не только длинные склейки.
