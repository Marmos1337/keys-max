# Обновление 0.3.0 → 0.3.1

**Это ZIP с исходниками, не выполненная выкладка.** Основа — предыдущий
`keys-max-0.3.0.zip`, не прочитанный с вашего сервера код. Более поздние правки
на сервере или в Codex необходимо сравнить и совместить.

## Что меняется

Визуальные компоненты и стили, оформление публичных документов, строки версии,
проверки и документация. **Схема остаётся 3; новой миграции для 0.3.0 нет.**
Серверная логика, бот, права, расчёты, API, правила начислений и файловый доступ
сохранены. При старте существующий worker работает как раньше — не путайте его
обычные плановые события с визуальным обновлением.

Для установки старее 0.3.0 сначала прочитайте
`docs/history/0.3.0/ОБНОВЛЕНИЕ.md`: там описана прежняя миграция в схему 3.

## Безопасная последовательность

1. Сохраните старый код/образ, рабочий `.env`, базу вместе с `uploads/`, текущие
   compose-файлы, сертификаты и настройки Nginx Proxy Manager. Копия должна быть
   доступна вне сервера и закрыта от посторонних. Для SQLite остановите изменения
   на время целостной копии; резервный скрипт не останавливает приложение сам.
2. Распакуйте архив отдельно и сравните с установленным проектом. Список отличий
   от поставки 0.3.0 — `docs/CHANGED_FILES.json`. Перенесите код, но **не заменяйте
   `.env`, постоянный том, загруженные файлы или рабочую конфигурацию примерами**.
   Токен MAX, секрет webhook и секрет сеансов не менять.
3. Для вашей существующей конфигурации NPM сохраните проект `keys-prod`, сервис
   `app`, контейнер `keys-app`, том `keys-prod_data`, домен и текущие порты. Не
   используйте `down -v`, новый project name, очистку volumes или новую пустую БД.
4. Пересоберите приложение привычной командой вашей установки. Для контекста,
   переданного вместе с предыдущим исходным кодом, это:

```sh
dc() { docker compose -p keys-prod -f compose.yaml -f compose.prod.yml -f compose.ca.yaml "$@"; }
dc config --quiet
dc up -d --build app
dc logs --tail=100 app
curl --fail --silent http://127.0.0.1:3002/api/health
```

Команды выполняются в действующем каталоге приложения. Если конфигурация с того
времени менялась, используйте вашу актуальную, а не заменяйте её этим примером.
Полный вывод `docker compose config` может раскрывать секреты; используйте `--quiet`.
Новая версия health/config — `0.3.1`. Порты 80/81/443 остаются у NPM.

## После запуска

Закройте и заново откройте Mini App, чтобы получить новые CSS и ES-модули.
Проверьте загрузку `/ui.js`, `/styles.css`, `/theme.js`, `/legal.css`, а также
доступность `/privacy` и `/terms` без входа. Не сбрасывайте пользовательские данные
ради обновления внешнего вида. При собственных правилах CDN/proxy проверьте кеш.

Откройте реальные аккаунты собственника и арендатора на Android/iPhone/компьютере.
Пройдите `ПРОВЕРКА_ДЛЯ_ЗАКАЗЧИКА.md`. Health не подтверждает работу бота, файлов
или мобильного интерфейса. Настройки webhook не менялись; повторная регистрация
из-за этого визуального обновления сама по себе не нужна.

## Если требуется откат

Сохраните диагностику и отдельную копию текущих данных. При переходе с 0.3.0
схема и формат данных не меняются, поэтому можно вернуть сохранённый код/образ
0.3.0 с прежней конфигурацией. Не откатывайте пользовательскую базу автоматически:
новые записи после обновления не должны потеряться. Для версий до 0.3.0 действуют
отдельные правила предыдущей миграции — см. историческую инструкцию.

Рабочий сайт и Docker-сборка в этой среде не проверялись. Файлы конфигурации
сохранены, но их пригодность именно вашей текущей установке проверяет администратор.
