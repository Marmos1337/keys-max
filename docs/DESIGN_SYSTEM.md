# Визуальная система «Ключи» 0.3.4

Это обновление представления, не новый продукт. Используются исходные иллюстрации,
логотипы и функциональные маршруты версии 0.3.0. Внешние UI-зависимости и шрифты
не добавлены. Размеры, цвета и формы больше не задаются отдельным набором правил
для каждого нового раздела.

## Где искать общие компоненты

`public/ui.js` содержит:

- `surface` — общую карточку/подложку;
- `listItem` — строку списка с ведущим элементом, содержимым и действием;
- `statCard` — числовую сводку; применяется на главной и в финансах;
- `segmented` — общий переключатель вкладок, фильтров и квартир;
- `actionTile` — быстрые действия на главной;
- `navigationRow` — текстовую строку профиля и переходы внутри квартиры;
- `pageTone` / `navPage` — цвет контекста и родительский раздел для детализации;
- `rememberStrips` / `enhanceUI` — сохранение положения полосы вкладок и
  показ выбранного элемента без сдвига всей страницы.

`public/utils.js` сохраняет прежние общие `button`, `notice`, `pillIcon`, `badge`,
`field` и форматирование значений. Кнопка по умолчанию теперь `type="button"`:
отправка формы выполняется только явно обозначенным submit.

`public/views.js` собирает страницы из этих элементов. `public/rental-ui.js`
сохранил логику аренды и форм; его существующие поля и действия получают общий
вид через те же классы. `public/app.js` по-прежнему обрабатывает прежние `data-act`,
`data-kind`, `data-id`; добавлены только оформление модального контекста и
восстановление положения вкладок.

## Токены

Все значения объявлены в начале `public/styles.css`. Базовая шкала отступов:
4, 8, 12, 16, 20, 24, 32 px. Карточки: радиус 24 px; вложенные элементы: 18 px;
обычные поля/кнопки: 16 px. Повторяющиеся размеры и мягкие тени используются
во всех разделах. Крупные изображения и модальные окна имеют согласованные
увеличенные радиусы, а не случайную форму.

Основные переменные: `--bg`, `--card`, `--field-bg`, `--text`, `--muted`,
`--shadow-card`, `--radius`, `--radius-control`. Тема изменяет токены в
`:root[data-theme="dark"]`, а не перекрашивает каждый экран отдельными правилами.

Цвет передаётся через `data-tone`. Доступны мягкий фон, подложка иконки,
контрастная кнопка и текст: `--tone-soft`, `--tone-icon`, `--tone-strong`,
`--tone-ink`. Одинаковые значения используют кнопки, вкладки, карточки и меню.

| Направление | Тон |
|---|---|
| Квартиры, комнаты, аренда | blue |
| Заявки и поломки | purple |
| Платежи, расходы, регулярные начисления | green |
| Счётчики и показания | amber |
| Покупки | orange |
| Посещения | teal |
| Документы | slate |
| Общая справочная информация | neutral |

Цвет направления не заменяет статус. Ошибка/удаление используют красный,
предупреждение — янтарный, успешный результат — зелёный. Метка содержит текст:
пользователь не обязан распознавать состояние только по цвету.

## Кнопки и поверхности

Основное действие — заполненная контекстная кнопка; вторичное — мягкая цветная;
вспомогательное — прозрачная текстовая. Все используют `.btn`. Контуры элементов
убраны; клавиатурная рамка фокуса намеренно сохранена. Не добавляйте произвольную
серую браузерную кнопку вместо общего компонента.

Пример:

```js
import { button } from './utils.js';
import { listItem, segmented } from './ui.js';

button('Новая заявка', 'new-record', 'data-kind="ticket"', 'primary');
segmented([['all', 'Все'], ['open', 'Открытые']], 'all', {
  act: 'filter', label: 'Заявки', tone: 'purple'
});
```

Текст пользователя обязательно экранируется через `esc`. `content`, `leading`,
`trailing`, `attrs` компонентов — доверенные шаблоны разработчика, а не произвольный
HTML из базы. Идентификаторы и проверки доступа на сервере не заменяются UI-кодом.

## Навигация и адаптация

На десктопе — фиксируемая при прокрутке округлая боковая панель. Текущий пункт
показывает цвет своего направления. На промежуточной ширине панель компактная;
на телефоне остаются шесть пунктов нижней навигации. Детальная карточка подсвечивает
родительский раздел: например, начисление — «Финансы», заявка — «Заявки».

Фильтры/вкладки — одинаковые округлые переключатели. На узком экране прокручивается
сама полоса, не документ целиком. Таблица/список не превращается в горизонтально
вылезающий блок. Полосы прокрутки тонкие; у скрытой полосы вкладок сохраняется
возможность прокрутки и клавиатурного доступа.

Формы используют одинаковые поля, подписи, селекты, загрузку файлов, чекбоксы и
переключатели настроек. Даты на телефоне не заставляют соседние колонки вылезать
за границы. Окна прокручиваются внутри; крестик/заголовок остаются доступными.

## Доступность и системные настройки

Используются текстовые статусы, `aria-current` у меню, `aria-pressed` у фильтров,
имена у кнопок-иконок, видимый клавиатурный фокус. Учтены `prefers-reduced-motion`
и forced-colors. Системный шрифт, общий ритм типографики, мягкий контраст подложек.
Это не сертификация доступности: скринридеры и устройства нужно принять отдельно.

Публичные `/privacy` и `/terms` используют те же токены и тему через `legal.css`.
Тексты разделов документов не менялись; менялась только оболочка.

## Как не вернуть разнобой

Сначала используйте существующий компонент и тон. Новый повторяющийся элемент
добавляйте в `ui.js`, правило — в соответствующий раздел `styles.css`, не в конец
файла очередным override. Не смешивайте inline background с `data-tone`.
Перед выпуском проверяйте светлую/тёмную тему, обе роли, узкие формы и состояния
«пусто», «ошибка», «ожидание», «выбрано». Команды — в `TEST_REPORT.md`.


## Исправления и проверка 0.3.4

Одна сетка парных действий (`action-row`, `heading-actions`) обеспечивает равные
ширины и высоты. Нечётное последнее действие занимает всю строку. Панель действий
записи больше не sticky: она не перекрывает детали и согласование. Общие списки
используют `records-list` с одним интервалом, включая вкладки квартиры.

Поля и select используют одинаковую высоту. Фоновый цвет задаётся через
`background-color`, чтобы не стирать стрелку раскрытия. Российский формат даты
показан в placeholder и доступном имени, а не расширяющей высоту подписи.

`data-fit-number` привязывает число и валюту к одной строке. `fitNumericLabels`
пересчитывает размер после рендера/изменения окна, не сокращая сумму. Очень длинная
сумма в статистике получает всю строку; сам текст не обрезается. Длинные имена и
подписи переносятся внутри контейнеров. Горизонтальная прокрутка предусмотрена
только для полосы вкладок/фильтров.

Шапка mobile: back / logo / notifications в фиксированных областях grid;
переключатель двух ролей — отдельная строка. У одной роли пустой строки нет.
Для низких окон компьютера sidebar прокручивается без минимальной высоты экрана.

Временный гайд — один общий компонент с состоянием. Он не выводится постоянно
в заголовке страницы; после освоения доступен только через профиль. Общие цвета,
радиусы и focus-visible сохранены. `tests/layout_audit.js` проверяет геометрию
этих компонентов на всех рассматриваемых страницах и формах.
