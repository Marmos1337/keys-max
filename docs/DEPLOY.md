# Развёртывание: существующий Nginx Proxy Manager

Для обновления сначала `../ОБНОВЛЕНИЕ.md`. Описанная ниже конфигурация основана
на предоставленном production-контексте, не на новом подключении к вашему серверу.
Сервер из этой сборки не изменялся.

## Состав

`compose.yaml` — приложение и постоянный volume data. `compose.prod.yml` — ваш
NPM overlay с container_name=keys-app и внешней сетью learnio_news_proxy_net.
`compose.ca.yaml` — read-only CA и NODE_EXTRA_CA_CERTS. Проект **keys-prod** оставляет
том **keys-prod_data**. В `.env` LOCAL_PORT=3002. Хостовый порт127.0.0.1:3002,
внутри Docker app:3000. Публичный трафик идёт через NPM в общей сети на keys-app:3000.

**Не запускайте compose.production.yaml из старого Caddy-примера на этом сервере.**
Он сохранён только как самостоятельный пример для другого чистого окружения.
80/81/443 уже принадлежат NPM; установка не должна их перехватывать.

```sh
docker compose -p keys-prod -f compose.yaml -f compose.prod.yml -f compose.ca.yaml config --quiet
docker compose -p keys-prod -f compose.yaml -f compose.prod.yml -f compose.ca.yaml up -d --build app
```

Используйте ровно эти project/overlays также для exec/stop/logs/служебных команд.
Не выводите полный compose config: он содержит secrets. Новая установка требует
постоянного диска, сети NPM, токена MAX и заполненного production.env. При обновлении
не создавайте новый .env вместо существующего и не запускайте seedDemo.

`extra_hosts` в присланном overlay сохранён без изменения. Если адрес сервера
меняется, его обновляет администратор вместе с DNS. NPM уже должен иметь HTTPS,
Force SSL и проксирование Web/API с одного origin. DATA_DIR нельзя публиковать как
статическую папку. Прямой внешний доступ к порту3000/3002 закрывается.

## Что проверить у прокси

Не кэшировать авторизованные /api/, скачивания, covers, export. Максимальный размер
файла приложения10МБ; лимит прокси должен пропускать такие запросы. Передавать Host
и X-Forwarded-For. TRUST_PROXY=1 используется только за одним доверенным прокси;
прямой вход с произвольным X-Forwarded-For не должен быть публичным.

Временные download/cover/export URLs содержат ticket в query. Не храните эти URL
в публичных access-логах. Практичный вариант для данного Proxy Host — отключить
access-логирование целиком на его server/location уровне (`access_log off;`) либо
использовать собственный формат только с `$uri`, без `$request`/`$request_uri`/`$args`.
Настройку вносить через поддерживаемый механизм вашей версии NPM, не править
генерируемые файлы контейнера вслепую. После изменения администратор проверяет
`nginx -t`, перезагрузку и фактические логи тестовым, не рабочим ticket. Ошибки
и аудит действий приложения при этом нужно продолжать наблюдать отдельно.
Приложение само конфигурацию NPM не меняет.

## Сохранность

SQLite WAL и uploads связаны: копия только живого keys.sqlite неполна. Backup
выполняется при остановленном app, с того же volume; `.env` и конфиги сохраняются
отдельно. Полная процедура, проверка и rollback описаны в ОБНОВЛЕНИЕ.md.
Нельзя применять `down -v`, `volume prune` или старый код к schema3.
Скрипт restore для native-каталога проверяет SHA-256 и SQLite, сохраняет прежнюю
папку рядом; очищает сеансы, invites и очереди, чтобы не повторить старую доставку.
Восстановление в Docker volume требует отдельной проверенной операции администратора,
не переименования корня примонтированного тома самим скриптом.

## Мониторинг

Наблюдать свободный диск, размер/резервные копии uploads, worker_error и outbox.failed.
Непривязанные вложения старше24ч очищаются, привязанные записи не удаляются автоматически.
Правила доступа/сроки хранения данных, права администратора и резервные носители
нужно настроить вне приложения. Диск и backups не шифруются самой программой.

Health `/api/health` возвращает version0.3.4/mode, но не проверяет Telegram/MAX,
доставку уведомлений, модерацию, сертификат сайта или успешность внешнего запроса.
Нагрузка, настоящие мобильные WebView и сборка Docker этой поставки локально
не проверялись. Один экземпляр Node и SQLite на локальном диске; несколько
реплик с одной сетевой БД не поддерживаются.

## Альтернативный локальный запуск без Docker

Node.js22.16+, `npm run setup`, `npm start`, localhost:3000. Это только demo.
Для native production сохраните существующий DATA_DIR и используйте свой
процесс-менеджер, HOST=127.0.0.1, HTTPS у прокси, правильные CA и закрытые secrets.
Не используйте чисто статический хостинг: нужны API, worker и постоянная база.
